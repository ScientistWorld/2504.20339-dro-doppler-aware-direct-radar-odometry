# Constraints

Future improvements must use the same benchmark and prediction contract for the existing score groups:

- Dataset: `data/synthetic_dro.npz` generated by `data/synthetic_radar.py`.
- Scenarios: `structured` and `tunnel`, with the same frame count, radar grid, beam timing, chirp signs, noisy gyro measurements, and ground-truth trajectories.
- Outputs: prediction JSON files with `method` and per-scenario `trajectory` entries. Each trajectory row must contain timestamp, x, y, heading, body-frame x velocity, and body-frame y velocity.
- Evaluation: `scripts/evaluate.sh` must read prediction artifacts and call only code under `eval/`; it must not import from `method/` or regenerate predictions internally.
- Dependencies: use the packaged `environment/container.def` and `environment/setup.sh` unless adding a clearly documented new experiment.

Valid changes must stay within the same sensor suite and odometry problem: estimate motion from the provided radar sequence, timing metadata, chirp metadata, range grid, and yaw-rate measurements.

Invalid shortcuts include using ground-truth poses or velocities at inference time, changing the generated trajectories to easier cases, fitting a supervised predictor to the benchmark ground truth, using external localization sensors, or reporting paper numbers instead of computed scores.
